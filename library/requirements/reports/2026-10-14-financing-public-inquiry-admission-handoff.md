## Durable admission and capture enforcement

The reserved additive migration is 20261014120000_financing_public_http.sql. It adds exactly one tenant table, campaign.financing_public_inquiry_admissions. The property branch tenant-table inventory increases from 39 to 40; the parent owns the scaffold update. The table has forced RLS, an owner policy, no public/app table grant, three foreign keys and indexes supporting location, publication and composite release references. Quota indexes cover publication/client/time and publication/time. New table/index locks and the short referenced-table FK/catalog locks are documented in the migration; lock_timeout remains five seconds. There is no existing-row rewrite or new customer role.

Defaults match the existing native funnel implementation at supabase/migrations/20261006230000_funnel_publication.sql:83-84: twenty new requests per client/publication in ten minutes and five thousand per publication in a rolling day. A publication advisory transaction lock precedes eligible protected scope resolution, counts and insertion. SERIALIZABLE admission transactions fail closed on conflicting native execution rather than allowing oversubscription. Exact UUID/client retries resolve before quota checks and take no second slot, including after a lost response. A changed client bucket for an existing UUID conflicts. Denial returns a bounded Retry-After decision and does not reserve a new row. Publication expiry, revocation, rights, host and current owner standing are rechecked before every admission, including replay.

Only a server HMAC client bucket, signed-request UUID, publication/release/tenant identities, timestamps and the existing keyed capture content hash are retained. The repository accepts trusted deployment client bytes under an explicit resolver policy; it never derives authority from forwarded visitor headers. The configured thirty-two-byte server key is copied, has no default and stays out of SQL. Publication UUIDs canonicalize before domain-separated HMAC, so UUID casing cannot create different client buckets for the same native publication. No raw address, contact, inquiry body or secret key enters the admission table or SQL arguments. Admissions are durable quota/replay metadata; this packet supplies no new cleanup schedule or alteration to existing thirty-day encrypted-inquiry retention and tombstone behavior.

The parent approved an additive same-signature capture wrapper. The old capture function is renamed financing_release_capture_private and its public/app execution grants are revoked. Its original prosrc body remains byte-identical, proven against the untouched original migration in the actual SQL regression. The wrapper occupies the exact former name/signature and grants the same public/app entry capability. For financing_public_runtime it requires the exact protected scope, publication, release and admitted request UUID, locks the admission, invokes the original guarded body, then consumes the matching keyed content hash atomically. No public direct call to the private body or unadmitted wrapper can bypass admission. Matching content returns the original receipt; different content conflicts. Failed capture rolls back consumption. The original body still enforces eligible source, current scope, thirty-day ciphertext lifetime and removed/purged-request tombstones. Owner app capture retains its original qualified behavior.

## Released API

PostgresPublicFinancingInquiryAdmissionRepository(publicPool, serverHmacKey32).admit accepts publicationId, canonicalOrigin, requestId and trustedClientKey: Uint8Array. The UUID must come from the server-issued signed request nonce, and client bytes must come from a separately qualified deployment policy. It returns allowed plus retryAfterSeconds, with zero for admission and one through 86400 for a limit. The HTTP runtime's existing success mapping to one second is compatible. Conflicting/unavailable/invalid native results throw sanitized FinancingReleaseError; unknown result shapes and driver failures become UNAVAILABLE. There is no automatic retry, in-memory limiter, fabricated principal, browser-selected tenant or permissive fallback.

Only a narrow explicit export group was added to packages/db/src/index.ts. The existing financing release implementation, contracts, data fixture and SQL file are untouched. The parent authorized one narrow extension to the existing integration suite: its anonymous capture case now first proves unadmitted denial, then performs legitimate native admission before the original successful capture and all original assertions. No cleanup finalizer, protected raw connection behavior or earlier negative assertion changes.
