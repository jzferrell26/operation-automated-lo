## Warnings and release holds

**QA-010-01, PostgreSQL qualification:** `apps/web/src/server/property-campaign-handler.ts:36-45` reuses the existing tenant-bound adapter, but the new property path has not been exercised against the real database. Add actual saved-brand/partner reads, cross-tenant denials, exact and altered retries, concurrent first-writes, and persistence/readback cases to the real-PostgreSQL suite before release. A clean inherited repository suite does not substitute for these cases.

**QA-010-02, review-runtime visual coverage:** `tests/browser/property-campaign-recovery.spec.ts` covers the real local synthetic runtime at 1440 and 390 pixels. That is not the first-party authenticated review-runtime matrix, not a Linux baseline comparison, and not the owner's visual sign-off. Desktop and mobile form/detail screenshots were inspected; they were readable with no cut-off controls or horizontal overflow. Screenshots remain ephemeral test evidence rather than new approved reference images.

**QA-010-03, data and abuse controls:** the security self-review records the missing creation quota, inherited retention/export/deletion work, and stale static CVE watchlist. Keep their release restrictions visible. No exception to a live-provider or data-policy gate follows from the new form.

**QA-010-04, discovery deliberately deferred:** the new preparation route is directly reachable and new campaigns appear in the campaign list, but it is not promoted into the default Home creation journey. Batch F governs promotion after usable generated outputs are proven; do not mistake a directly tested route for a finished first-run experience.

## Suggestions

Display event times in the user's selected property/event time zone when Batch B introduces scheduling and published materials. The current form explicitly uses the device's time zone and the saved page explicitly shows UTC, preserving the correct instant without pretending the property supplied its own time zone.

When reviewing the diff, start with the save boundary and strict manifest extension rather than the copied field wiring. This is one end-to-end preparation slice, but its test and documentation additions exceed the small-PR guideline; later generation/provider work should remain separate PRs.
