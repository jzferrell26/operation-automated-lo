## Concrete supported paths

The binding factory validates its server signing configuration and mandatory functions before allocating work. It requires distinct request and admission pools. Object inequality is an accidental-pool-reuse check, not proof of database login capability; the existing admission SQL grant and a separate deployed capability login remain authoritative. There is no environment activation, fallback identity, in-memory production state or default accepting verifier.

It constructs the existing HMAC task authority and the existing concrete Postgres/native worker runtime. Current authentication gets only actor/location UUIDs, never serialized roles or signing configuration. The returned principal is frozen and checked for canonical actor/location correspondence, current location_admin authority and non-synthetic authentication. Existing database authority is rechecked against the current principal without selecting a replacement role or extending a session. Current preflight and source evidence use the existing application helpers, followed by the mandatory source/lender/database authority service.

The media adapter obtains actual immutable PNG bytes and a persisted provider lease from the required neutral media service. It rechecks principal and current authority after that asynchronous retrieval. The existing verifier checks the PNG structure, exact reviewed digest/length, 1080 by 1080 geometry, provider storage origin, file identity and delivery expiry through the approved end date. This adapter performs no upload or arbitrary URL fetch and cannot manufacture a media lease from a shaped receipt.

Response verification remains a mandatory actual-capture capability, separate from the SQL admission verifier. The observation mapping parses the actual linked DTO and checks its independently computed normalized hash. It binds the candidate to the actual response time, operation projection, retained identities, current lifecycle classification and actual Facebook IDs. Unknown linked metrics remain null; even invented zeros are rejected. Candidate expiry and receipt/normalized observation time must remain valid. Metadata comes from the durable artifact service; the independent admission verifier still checks provenance before the separately privileged login persists anything. A successful strict mapping test proves normalization, not verified_provider provenance or App Test standing.

The accepted relay alternative is an in-process, at-least-once delivery. It uses the actual publisher repository for a bounded oldest-item pending scan and worker record read, with the existing serializable tenant context and database authority. It checks immutable task/action/projection/correlation/operation identities, actor/version and current principal before signing an exact server-built request. The HMAC covers that exact request, actor/location and a lifetime no longer than sixty seconds or the operation deadline. It invokes the existing runtime directly, using a fifty-second abort signal; existing repository statement/lock limits and worker stage/lease limits remain in force.

Each scan attempts at most one item. Active leases, completed work, exhausted operation deadlines and abort stop invocation. A crash before invocation leaves the original outbox pending. A crash or lost acknowledgement during provider work is handled by the existing consumer's retained attempt, generation/cancellation CAS, uncertainty and reconciliation. This relay never creates provider entities itself, searches for guessed IDs, retries a write, claims a broker accepted work, records a Trigger submission acknowledgement, or marks the outbox processed. SQL terminal completion owns the outbox. Overlapping relays may deliver the same task, which the existing worker and database lease must fence.

The one-oldest-item policy is intentionally bounded. An old unresolved operation can hold this scan pending; production scheduling/fairness and operator reconciliation policy remain required engineering decisions, not hidden retries or a new SQL claim primitive. No periodic scheduler or task export was added. A schedule owner must route the trigger separately before activation.

## Confirmed source gaps and minimal next interfaces

These are implementation gaps, not just missing credentials. Parent accepted the bounded relay and queued authoritative authentication/source extraction work; no new contract revision or numbered DDL is accepted by this handoff.

1. **Immutable authentication bootstrap.** The task proof contains actor/location IDs. The operation retains actor and role version, but it does not expose the originating session, installation and authentication provenance before a principal exists. Existing web session lookup needs a secret; its session-ID predicate proves activity without returning exact ownership. The required neutral service needs resolveCommandPrincipal({ operationRef, actorId, locationId }) bound to persisted server-verified command provenance, then revalidatePrincipal(original) checking the exact session/installation/role/version and current revocation/expiry. It must not choose any newer active session for that person. Signed embedded provenance requires its actual existing verification and session lifecycle, not a stored caller boolean. The relay scanner's separately authorized owner scope is read-only; it cannot become the spending command's original principal. Current new-file authentication.current(actorId, locationId) is a mandatory placeholder capability contract whose concrete original-command resolver is absent. A per-command closure or a separately reviewed runtime API extension to include operationRef is needed before deployed wiring.
2. **Neutral current source and raster extraction.** Current source/destination/registry/raster implementations are in apps/web/server-only modules, notably webinar-ad-evidence, webinar-ad-art, webinar-ad-raster and webinar-destination. Tasks cannot import that application. Extract a package-owned service preserving exact authenticated publication ownership, current CTR-002/lender release, registry hashes/rights, fixed contained asset paths, pinned font/glyph bytes and deterministic approved raster regeneration. The existing WebinarAdEvidencePort is consumed here, but its neutral production implementation is not built.
3. **Persisted provider media lease.** readMediaBytes(principal, record) must load exact tenant/projection/creative bytes plus the verified actual HighLevel fileId, allowlisted provider URL and lease expiry from durable owned storage. Media schema validation is not lease provenance. No such publisher media repository or upload/capture persistence is supplied by this packet.
4. **Durable actual native capture and independent admission verification.** The native fetch boundary must durably record a sanitized actual response artifact and verification metadata bound to operation/action, tenant/account/parents/IDs, exact native request hash, response digest, actual receipt time, expiry and pinned wire mapping. The verifier must read and independently decode those stored actual bytes and current qualification. It must have separately provisioned authority; response-shaped app_test or verified_provider values are insufficient. The frozen native transport returns request/normalized hashes but no durable artifact handle; a separately reviewed capture-aware fetch wrapper and durable store/service are still required. Never persist tokens or log raw payloads. The required existing verifyResponse, responseAdmission and admissionVerifier ports remain unimplemented in deployed composition.
5. **Reviewed wiring and deployment proof.** After the services above exist, authorize changes to the existing frozen task/runtime accessor and task index, bind each original operation's authentication scope, compose the separate admission login, configure the actual location token resolver and signing key server-side, then register the bounded relay/safety schedules. Purchases, controlled provider calls and live launches remain deliberate separately authorized steps. G2 and other deferred external evidence dispositions remain unchanged.

No additional relay claim/ACK DDL is necessary for the accepted in-process alternative. The generic delivery guard is not repurposed: its claims lack a crash-expiring relay lease and cannot substitute for the current worker's existing lease/reconciliation semantics.
