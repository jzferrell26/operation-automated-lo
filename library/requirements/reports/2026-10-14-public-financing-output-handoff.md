Only the existing financing-release-pdf.ts and financing-release-output.unit.test.ts changed. A request-local subclass of the existing exact pdf-lib 1.17.1 PDFParser preflights actual PDF object syntax before PDFDocument.load. It uses the package's exported parser and protected parse methods, checked by the project compiler, without a global prototype/module patch. Every actual name token containing a hash escape is refused before normalization, whether uppercase, lowercase, mixed, malformed, a key or a value. This is a deliberately smaller qualified Chromium subset, not a general PDF-name decoder or arbitrary uploaded-document promise. All original renderer output names continue to qualify.

The preflight identifies dictionary keys at their parser depth and refuses repeated keys before the library's Map can overwrite an earlier value. Thus both literal duplicates and escaped aliases cannot conceal conflicting action authority. It applies to nested inline dictionaries, array descendants and independently parsed indirect objects, rather than matching raw bytes throughout a file. Literal strings, comments and binary stream payloads remain handled by the actual parser and are not scanned as name tokens. Parsing is bounded to depth 64, 200,000 object/name tokens and 1,024 bytes per name, within the existing 20 MiB document admission limit. Object/xref streams, indirect stream Type fields and inexact stream-end recovery are outside this actual producer subset and fail closed. Strict invalid-object loading is enabled. Existing finite object graph, action-only Type/S/URI policy, exact approved canonical binding, financial/text/image/font/identity/disclosure/validity parity, private object ownership and renderer limits remain in place.
