## Findings

### Critical (must fix before the listing is submitted)

- [ ] **F-01. Install, "runs inside HighLevel", "no separate login", and uninstall claims are false, and `P1` cannot clear by operator action.** `next.config.ts:8`, `content-security-policy.ts:38`

  Claims: `what-is-automated-lo.md:5, :21, :32`; `open-house-boost-faq.md:31-32`; `copy pack:43, :56, :61, :152, :158, :176, :184`. The product has its own email and password sign-in, and `docs/operations/review-surface.md:68` says "Signing in here proves nothing about HighLevel. It is this product's own login". The signed-in shell says "HighLevel, Meta, and Stripe aren't connected yet" (`user-language.ts:22, :143`). Live OAuth and signed-context exchange are disabled (`packages/ghl/src/live-oauth-disabled.ts:1-6`); the embedded session port stays undefined "until the HighLevel signed-context exchange exists" (`runtime-authentication.ts:257-261`). `InstallationLifecycleService` (`packages/application/src/tenant-installation.ts:71`) is referenced by no route, so no uninstall is handled. There is no OAuth callback or webhook route under `apps/web/src/app/api/`.

  The deeper problem is that the gate `P1` names ("Test Link install must succeed") cannot succeed. HighLevel renders Custom Pages in an iframe and says not to return `X-Frame-Options: DENY` or `SAMEORIGIN` and to allow HighLevel in `frame-ancestors` ([Custom Pages](https://marketplace.gohighlevel.com/docs/marketplace-modules/CustomPages/), read 2026-10-01). The app returns both:

  ```ts
  { key: "X-Frame-Options", value: "DENY" },
  "frame-ancestors 'none'",
  ```

  Suggested: remove every install, "inside HighLevel", "no separate login", and uninstall sentence until the G2 track (`GGL-B10`, the 28 `DEFERRED: LIVE HIGHLEVEL AUTH` rows) changes the headers and implements the exchange. Replacement wording is in R-1.

- [ ] **F-02. "Brand, compliance, and partner settings" do not feed campaigns.** `apps/web/src/server/open-house-draft.ts:92-94`, `apps/web/src/features/guided-setup/model/profile.ts:85-97`

  Claims: `overview:23, :28`; `faq:42`; `copy pack:45-46, :57, :153-154, :177-178`. The saved version points at constants, not at anything the user set up:

  ```ts
  brandProfileVersionRef: "brandprofile_local001",
  complianceProfileVersionRef: "complianceprofile_local001",
  partnerProfileVersionRef: "partnerprofile_local001",
  ```

  The guided setup collects name, company, optional NMLS number and phone, and a Realtor name and optional brokerage (`profile.ts:25-34`, `guided-setup-messages.ts:53-67`). Only the Realtor's name reaches the campaign form; headline, body, call to action, disclosure, and consent are starter constants (`profile.ts:49-56`, `:85-97`). Company, NMLS, and phone feed Homeowner report branding (`workspace-page-data.ts:57-62`), not campaigns. No setup step collects "compliance requirements" or "brand details" beyond a company name. R-2.

- [ ] **F-03. Homeowner reports contradict the absolute negatives, and nothing in the 004E set mentions them.** `apps/web/src/app/(authenticated)/layout.tsx:162-175`, `apps/web/src/app/(public)/home-report/[secret]/page.tsx:17-26`

  When `OALO_HOMEOWNER_REPORTS=enabled` (default off, `homeowners/runtime.ts:21`), the shipped product has a "Homeowner reports" navigation entry, a public page at `/home-report/<secret>`, a printable and PDF report (`shared-report.tsx:45`), a homeowner "Request a review" button whose result the loan officer sees as "<name> requested a review ... Follow up in HighLevel" (`workspace.tsx:526-531`), monthly refreshes, and an optional HighLevel workflow handoff. It stores the contact id and name, the property address, mortgage inputs, valuations, and share links in seven tables (`supabase/migrations/20260924010000_homeowner_reports.sql:22-121`, `contact_name` at `:27`). Activation behavior is documented in `docs/operations/homeowner-avm-activation.md`.

  Contradicted claims: "one focused workflow" (`overview:21`, `:64`; `copy pack:43`); no "public page, flyer, PDF" (`overview:39`; `copy pack:65`, `N2`); no lead capture or notice (`overview:41`; `faq:79`; `copy pack:67`, `N4`); no text or email (`overview:43`; `copy pack:69`, `N6`, conditional on `OALO_HOMEOWNER_DELIVERY_ENABLED`); "does not keep a duplicate borrower database" (`copy pack:72-73`, `N8`); "What data does it store?" (`faq:95`, `P11`); and the disclaimer "it ends there" (`copy pack:111-113`).

  No 004E document, 004C, the submission packet, the runbook, or the preview smoke pack contains the word "homeowner" (searched 2026-10-01), and none records the flag as a gate. The project map records the hosted app exercising the report API, so the review URL may expose the module. Either disclose it (R-3, option A) or make "`OALO_HOMEOWNER_REPORTS` unset on the review deployment" an explicit gate row (option B). Both options scope every negative to Open House Boost.
