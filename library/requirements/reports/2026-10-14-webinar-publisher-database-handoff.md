## Database and migration

Target is PostgreSQL 17, matching `supabase/config.toml`. The existing `postgres` 3.4.9 pool, unnamed statements and transaction pooling remain in use. Only assigned migration `20261014050000_webinar_publisher.sql` is authored. It creates five empty tables: verified admissions, immutable launch snapshots, operations, a dedicated strict task outbox, and unique operation-stage attempts. Source and selection snapshots are entire-read JSON; tenant, owner, installation, identity, stage, active status, lease and deadlines are indexed/typed columns. All FK column prefixes are covered by indexes.

This is expand-only. CREATE TABLE and CREATE INDEX take ACCESS EXCLUSIVE and SHARE locks on new empty tables. Foreign-key creation briefly locks referenced existing tables with SHARE ROW EXCLUSIVE; migration lock timeout is five seconds. Functions/grants take catalog locks. There is no existing-row backfill, destructive DDL or concurrent index left running. Roll forward after durable use; an unused disposable deployment can drop new functions/tables in reverse dependency order. This is not a production rollback authorization. Guidance: db-weapon `guides/01-schema-design.md` (whole-read snapshots versus queried columns), `guides/02-indexing.md` (FK prefixes and partial indexes), and `guides/03-migrations.md` (lock classes and expand-only deployment).

All new tables force RLS and have no ordinary app/support table grants. Request and worker access is through fixed SECURITY DEFINER functions with empty search paths. Admission is separately executable only by `publisher_admission_runtime`, a NOLOGIN, NOINHERIT role. The migration grants no login membership to that role. It does not use an application-settable custom GUC as an admission capability. Ordinary `app_runtime`, browser, anonymous and support roles cannot insert provider admission or call its function.

## Concrete application consumer

`PostgresWebinarPublisherRepository` implements the existing `WebinarPublisherCommandRepository.run` and all six transaction methods. It reuses the existing principal-bound tenant transaction and upgrades BEGIN to SERIALIZABLE before context queries. Local lock/statement limits are three and ten seconds. There is no production in-memory fallback or automatic serialization retry; a rejected transaction has no provider effect and must be retried through the original command identity.

The required server authority resolves the exact current principal before and after work. Database functions additionally lock actual active workspace/user, sole-owner internal binding/version, active installation, and matching unrevoked/unexpired first-party session. Embedded session signatures remain a required trusted server resolver responsibility; the database does not pretend a JSON mode proves a signed session. `currentPrincipal` must be read-only while these locks are held, so a separate-pool session touch cannot deadlock the transaction.

`loadCurrentEvidence` locks the current owned aggregate, latest immutable version, latest passing preflight, latest approved sole-owner decision and owner-bound publication. Source rows must match current campaign standing and hashes. The strict version/preflight/approval decoder preserves required nested nulls and omits only absent optional sourceCampaignRef. The required source authority checks registry, actual raster, publication and real lender standing on load and again before commit. New source admission is not fabricated when infrastructure is empty.

`resolveSelection` returns only a currently admitted exact selection for this owner/installation and actual stored HighLevel location binding. It rejects unknown discovery. `insertSummary` checks canonical projection/summary hashes and saved-source binding. `loadLaunch` returns immutable summary plus separate row/state/native IDs. `findCommand` is tenant/actor/request-UUID scoped. `reserveCommand` reconstructs the exact normalized command hash and confirmation hash, checks current native IDs/CAS/state, and atomically writes operation, lineage reservation and exact task JSON. Unknown revisions, arbitrary task keys and request conflicts refuse. The original immutable operation identity remains unchanged during checkpoints. The partial unique index enforces one active lineage per projection.

New spend actions recheck the existing `campaign.publish` platform authority and lock its latest actual entitlement row. No product price or entitlement is created by this feature. Cancel and owned pause do not depend on an expired creative, withdrawn destination or a paid entitlement that has ended.

## Trusted admission service

`createWebinarPublisherAdmissionService(pool, verifier).admit(principal, candidate)` requires a separate explicitly configured capability pool and a real provenance verifier. Neither is defaulted or elevated from the request pool. Before SQL it strictly parses only the verifier's normalized output; raw discovery bodies, page access tokens, unknown keys and synthetic qualification cannot enter the record.

Admission kinds are selection, qualification, pause and observation. Each retains verifier/admission reference, actual artifact hash, observed/expiry time and normalized data. Selection also names independently verified lender-release evidence. The integration service must verify real captured artifact provenance, correct account/page ownership, permitted geographic mappings, lender release and exact wire/media evidence. A fixture verifier is used only in tests. App Test-shaped JSON alone cannot obtain the SQL capability. A production implementation of this trusted verifier is the next server integration task.

`qualifiedProof(principal, projectionRef, kind)` reads only a current matching admission. Qualification checks exact projection/native asset/wire/budget/UTC end and expiration; pause is independently bound to the confirmed owned campaign. Observation stores decoded provider standing, separate Facebook entity IDs and nullable metrics. Live requires all real entity IDs. Provider standing/freshness is separate from a local task's lifecycle and can be shown separately by the reporting consumer. No metric is guessed.

## Durable worker APIs

| API                                                 | Boundary                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pendingTasks(principal, limit)`                    | At most 50 exact tenant-owned active outbox tasks; current authority required. No source, token or copy duplicated into messages.                                                                                                                                                                                                                                            |
| `readWorker(principal, operationRef)`               | Current owned operation, immutable launch, bounded deadline, worker/lease expiration and cancellation generation.                                                                                                                                                                                                                                                            |
| `claim(principal, {task, workerRef, leaseSeconds})` | Exact persisted task/revision matching; lease 1 to 60 seconds; incrementing generation; original 15-minute operation deadline. Another active lease is busy. An abandoned potentially dispatched stage becomes uncertain/reconcile.                                                                                                                                          |
| `beginDispatch(principal, input)`                   | Rechecks current authority, native ownership, source/media/wire through the required authority, then atomically records a unique operation-stage attempt before any possible send. Repeated dispatch at that stage refuses, even with a replacement generation.                                                                                                              |
| `checkpoint(principal, checkpoint)`                 | Exact worker/generation/unexpired lease/expected stage/cancellation fence, legal stage/state transition, immutable confirmed parents, matched request/read-back hashes and actual provider observation. The required server authority verifies independent decoded responses. Live/progress reconciliation additionally requires a separately admitted matching observation. |
| `markUncertain(principal, input)`                   | Preserves a possible effect and moves to uncertain/reconcile without another provider call. A stale worker cannot write.                                                                                                                                                                                                                                                     |

The worker must commit beginDispatch before invoking the native transport. Failed/lost/invalid responses and local checkpoint loss require reconciliation using trustworthy native identity; no display-name lookup or blind re-creation is authorized. An abandoned attempt is conservatively possibly applied even if a worker crashed just before sending. A bounded deadline terminates queued work as blocked, or ambiguous effect as uncertain, rather than making control wait indefinitely.

Cancel/pause controls fence an older active operation and advance cancellation generation atomically. A queued cancellation with no possible effect completes locally. Any old possible or confirmed effect remains uncertain/reconcile, never falsely recalled or deleted. A late worker loses checkpoint/dispatch authority. A newly owned pause can still use its own current transport proof when the original source/media expires. Automatic system safety-pause authority, actual provider execution, polling and worker scheduling are subsequent consumers.
