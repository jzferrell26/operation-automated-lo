## Critical Issues (must fix)

- [ ] **The PRD-005e operator ask names three variables the application no longer reads and omits the step that creates the credential** - `library/requirements/in-work/prd-005-authenticated-review-runtime/prd-005e-authenticated-review-runtime-deployed-qualification.md`, section "Exact operator ask", asks 2, 3, 4 and 5; repeated in the shipped document `docs/operations/evidence-packs/reviewable-preview-smoke.md:34`

  `ARR-006` and `005E-AC-004` through `005E-AC-012` and `005E-AC-016` are BLOCKED on this ask and on nothing else. As written it cannot be executed on the tree it ships with. Ask 2 tells the operator to set `OALO_REVIEW_SIGNIN_SECRET`, `OALO_REVIEW_LOCATION_ID` and `OALO_REVIEW_OUTSIDER_LOCATION_ID`; PRD-006a D9 removed all three, and `docs/production-environments.md:57` says so in terms ("The application reads none of them."). Ask 3 is wholly obsolete: it asks for 32 random bytes to be generated for a persona sign-in page that no longer exists, and promises "You will type it into the sign-in page yourself during the proof", but `/sign-in` now asks for an email and a password. Ask 4 omits `--set-password`, which `006A-AC-029` makes the only way to create the seeded credentials, and tells the operator to paste the printed ids back into two deleted variables. Ask 5 then says "Sign in as `creator`, `approver`, and `outsider`" with no password having been set. An operator who follows the document of record sets three dead variables, generates an unused secret, and arrives at a sign-in form they have no credential for.

  The corrected ask already exists in two places, so this is a reconciliation gap rather than missing work: PR #67's body carries the right five asks (including `--set-password` and the note that "no variable takes them any more"), and `docs/operations/review-session-seeding.md` is correct end to end and was verified line by line by `runbook-writing-guardian`. Suggested: replace 005e's "Exact operator ask" section with the PR body's five asks and point `reviewable-preview-smoke.md:34` at `docs/operations/review-session-seeding.md` instead. `library-guardian` owns the PRD text; this Guardian does not rewrite plans. The PRD-006 index's supersession table should also gain a row for PRD-005e's operator ask, which it does not currently list among the documents PRD-006 changes.

  3. **The review sign-in secret.** Generate at least 32 random bytes

     OALO_REVIEW_SIGNIN_SECRET on Vercel and in your password manager, and keep it.
     You will type it into the sign-in page yourself during the proof.
