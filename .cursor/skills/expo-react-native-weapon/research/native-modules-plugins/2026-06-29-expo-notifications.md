# expo-notifications (official Expo docs)

## Summary
expo-notifications (install `npx expo install expo-notifications`) handles local and remote (push) notifications, wired via a config plugin (icon/color/sounds/channel props). Push tokens come from `getExpoPushTokenAsync` (Expo Push Service) or `getDevicePushTokenAsync` (raw FCM/APNs). Critical 2026 fact: remote push does NOT work in Expo Go (from SDK 53 on Android, and effectively both platforms) - a DEVELOPMENT BUILD is required. iOS needs the APNs entitlement (auto-handled: development in debug, production in archive); Android needs FCM.

## Key quotations / statistics
- Install: `npx expo install expo-notifications`.
- Config plugin props: `icon` (Android push icon path), `color` (Android tint, default `#ffffff`), `defaultChannel` (Android FCMv1 channel), `sounds` (both, array of .wav paths), `enableBackgroundRemoteNotifications` (iOS, enables `UIBackgroundModes`).
- Token APIs: `getExpoPushTokenAsync(options)` (Expo token for Expo Push Service); `getDevicePushTokenAsync()` (native FCM/APNs token).
- iOS: "The iOS APNs entitlement is always set to 'development'. Xcode automatically changes this to 'production' in the archive generated by a release build."
- Android: requires FCM; notification channels mandatory on Android 8.0+.
- Expo Go limitation: "Push notifications (remote notifications) functionality provided by expo-notifications is unavailable in Expo Go on Android from SDK 53. A development build is required to use push notifications." Local notifications remain available in Expo Go; remote push requires a development build.

## Annotations for weapon-forge
- Document the Expo-Go-can't-do-push gotcha prominently - it surprises beginners and is a frequent "why doesn't my push work" support question. The fix is a development build (ties back to the EAS dev build profile).
- iOS push requires a real Apple Developer account + APNs key; Android requires a Firebase project + `google-services.json` (added via the plugin / app config). Mention the cross-dependency on app-store-submission-guardian territory for the Apple/Google account setup, but the wiring (plugin props, FCM file, entitlement) is this Guardian's lane.
- `getExpoPushTokenAsync` (use Expo's push service, simplest) vs `getDevicePushTokenAsync` (BYO FCM/APNs sender) is a decision to document.
- Physical device required for push token acquisition (simulators cannot receive remote push).
