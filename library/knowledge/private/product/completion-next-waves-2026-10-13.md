## Starting point and execution order

The current ledger records fifteen pending-review webinar variants with thirty raster files, a preparation interface, clearer report entry points, a dependency patch and local security/quality close-out. [PR #90](https://github.com/jzferrell26/operation-automated-lo/pull/90) still needs its remaining CI and baseline qualification. Finish that owned batch before allocating new changes on top of it. A preparation download is not a branded provider-ready export, an approved catalog entry or a campaign bound to a published webinar.

The financing engine and private text report already exist. Its manifest uses template `1.0.0` and `images.max(0)`; `financing-save.ts` stores no images. PDF bytes are generated on authenticated request. Homeowner reports already have the calculation, persistence, sharing and scheduler engines. The read-only production variable-name inventory records neither `OALO_RENTCAST_API_KEY` nor `OALO_HOMEOWNER_ALLOWED_LOCATION_IDS`; it does not prove deployed flag values, provider rights or usable allowance.

Proposed order:

1. Close PR #90 and freeze the shared contracts below against the resulting current `origin/main`.
2. Run disjoint homeowner capability and financing media increments. Begin webinar destination binding once its shared manifest/approval contract is settled.
3. Complete private photo report/flyer/site rendering and branded webinar export, then obtain the corresponding owner reviews.
4. Implement remaining exact-output/public-release and provider command work in separate owned increments.
5. Qualify authorized hosted and provider journeys, then record the specific outcome evidence. Keep incomplete external checks open.

At implementation start, branch from current `main`, reconcile existing work and assign every file to one owner. Use the ledger's available inherited GPT-6 mapping for bounded lanes. Each implementation increment closes with security review, then quality review; fixes invalidate affected earlier evidence. Rebase against current main, finish required CI and confirm MERGEABLE before presenting a PR as ready. This document performs no implementation, migration, deployment or provider activation.

## Release evidence and stopping conditions

Every increment's report names the exact source criteria, implemented subset, current commit, commands run and actual environment tested. Passing local fixtures does not close hosted/provider criteria. The review ledger must distinguish prepared, approved, published and externally delivered states and retain earlier test failures until the corresponding fix passes.

Public financing must prove `PAY-005`, `010` through `014`; the five visitor journeys must prove applicable `FUN-004` through `010`. Custom-domain `FUN-005` and `006` stay with #87 and require its full implementation, security/quality, required green CI and an authorized hostname/TLS/submission walkthrough. Recheck its current state before scheduling integration rather than reusing its earlier failure as today's result.

Proceed with repository implementation where contracts and ownership are settled. Stop only the dependent action when a required owner policy, source right, credential, publication approval or live-operation authorization is missing, while continuing independent work. G1, G4 and G8 retain their accepted-constraint disposition; none is reopened by this plan. No outcome is complete merely because its private output is attractive or a launch control is visible.
