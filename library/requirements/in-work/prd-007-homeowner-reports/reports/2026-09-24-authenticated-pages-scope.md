# Authenticated workspace completion

Jonathan requested continuing the project beyond the AVM milestone. Inspection after PR69 found that every catch-all workspace page still required dashboard-preview mode. The signed-in navigation therefore linked to routes that returned 404.

This correction makes every existing workspace destination resolve behind the established first-party session. Marketing and settings hubs link to working campaign and homeowner-report paths. Asset views list actual saved records without inventing public publication URLs. Provider-dependent pages state what connection is unavailable and link to the relevant setup. Unknown routes render the not-found page and no workspace data. Next.js may already have streamed a parent loading boundary with HTTP 200; the browser checks the not-found document and its noindex directive as well as the response status. This is the documented behavior at `https://nextjs.org/docs/app/api-reference/file-conventions/not-found`.

Personal report branding, Realtor partner entries and message drafts are saved to the existing tenant-and-user-scoped preference store. Branding supplies new report defaults; it never edits old report snapshots. Partners can be selected for new campaign inputs without asserting marketing permission. Message drafts can be copied for review in HighLevel; saving or copying does not send a message or start a workflow.

Preference writes use strict schemas, the established CSRF and session checks, a closed key allowlist, bounded JSON and an explicit revision. Concurrent edits cannot silently replace newer data. Exact retries are idempotent. Personal settings are scoped to the signed-in user within the current location, and are not represented as a shared company roster or a copy of the CRM. Support cannot read these settings through this endpoint. Viewer roles remain read-only.

Acceptance: authenticated navigation and unknown-route behavior; persisted branding reaches the report builder; partner CRUD and selection persist; message drafts persist per channel; failed/conflicting writes preserve edits; another user or location cannot read or overwrite the records; no provider call occurs from these page reads or preference writes; desktop, mobile, keyboard and both themes pass browser checks. Live RentCast, HighLevel, Meta and billing activation still depend on their own credentials and evidence.

The final report interaction review also covers the existing report detail page: save failures must be visible inside its open dialog, canceled schedule edits must reopen from saved values, pending commands must not overlap or dismiss their form, missing clipboard support must have a manual-copy path, and an owner must be able to remove a property whose first valuation failed. Removal reuses the existing authorized command and retains the database's minimal usage evidence.
