# Webinar publisher application command handoff

Date: 2026-10-14 UTC. Author: `/root/publisher_commands`, TypeScript/Node Guardian. Base: native foundation commit `7f144e9f4fe35a499c555f1d2e170e6a40e6f49c`. Governing agreement: accepted CTR-003 revision 1, SHA-256 `dfc912bfa9f00892641936794ce0488adc1fdea3df6bdf7a997cb8f00a48fe23`.

This increment implements strict shared schemas, summary derivation and confirmed application commands through required server authority and atomic persistence interfaces. It contains no production database implementation, worker, HTTP route, UI, provider call or deployment. Independent Security then Quality remain the parent's next review steps.

## Implemented boundary

- `prepareWebinarPublisherSummary` parses only saved campaign/version/hash hints and selected opaque resource references. It loads the actual current owned approved version, verifies a current passing preflight and exact original approval snapshot, and freshly consults CTR-002 evidence. It derives destination UUID, source/art, advertiser, unchanged words, square digest/dimensions, placement, budget and effective end from that saved source. Current server discovery resolves connected assets and permitted places. Every approved place must have exactly one selected native geography. There is no new copy, URL, receipt, timestamp or asset authority accepted from the browser.
- The projection uses the existing canonical campaign hash. The test passes the actual application-produced projection through `assertWebinarPublisherProjection` from the native adapter. The saved `meta.enabled: false` manifest stays unchanged.
- `webinarPublisherConfirmationHash` binds the action, complete summary, complete projection and current native parent IDs. `executeWebinarPublisherCommand` checks current sole-owner authority and lineage ownership before every action and successful replay. Draft/publish/resume additionally regenerate current evidence and resolve the same selections. Their capability proof must match the exact projection/account/budget/end and be currently valid. The server authority must verify actual proof provenance; a schema alone does not qualify an installation. Default production mode rejects `local_synthetic`.
- Pause uses a separate current transport qualification bound to the owned native campaign and exact projection. It does not require an expired creative, destination or budget qualification lease. Cancellation is a local control; its trusted authority must fence or reconcile any concurrent remote write. Neither action retargets or changes spend inputs.
- Each new command supplies one immutable operation and one strict outbox task to an atomic repository reservation. Successful exact replay returns the original operation without reserving another task. Reused request identity with different content, stale row/evidence, mismatched confirmation and incompatible lineage state refuse. Async reservation is `reserved`, never provider-live evidence. Results contain only operation/action/state/duplicate/correlation.

All interface tests use injected synthetic ports and responses, including synthetic data labeled as an App Test-shaped proof. They establish no actual App Test or production qualification. The in-memory serialized repository exists only inside the unit test, not production source.

## Exact database consumer handoff

The database Guardian owns DDL, the assigned migration and actual PostgreSQL qualification. Implement `WebinarPublisherCommandRepository` and `WebinarPublisherCommandTransaction` as real tenant-scoped serializable transactions. No fallback in-memory implementation is acceptable.

1. `run` derives its tenant context from the authenticated principal, verifies current session/installation/sole-owner role-version authority, and retains applicable current evidence and lineage locks through callback completion. Current principal provenance is not the role serialized in an older operation. `loadCurrentEvidence` must load the campaign's current immutable version, current preflight and current unwithdrawn decision, not an arbitrary requested historical version. The version creator and approving actor must be the sole LO.
2. `resolveSelection` resolves the submitted owned `adAccountRef`, `pageRef`, square `creativeAssetRef` and ordered `geographyRefs` against server discovery. Return the strict `WebinarPublisherResolvedSelection`: matching account/page refs, native assets plus discovery hash, safe account/page labels, ordered native geography entries with `selectionRef` and exact manifest `approvedPlace`, the qualified provider contract and honest total-budget semantics. Confirm connection currency, account/page linkage, installation location and current discovery. Never persist page access tokens or raw discovery bodies. Empty/unqualified infrastructure must refuse, not return fabricated connected assets.
3. `insertSummary` reserves the immutable `WebinarPublisherSummarySchema` and returns `WebinarPublisherLaunchRecordSchema` with row version 1, state `reserved` and all native IDs null. `loadLaunch` scopes by projection ref and current tenant/owner, never a client native campaign ID. Retain summary/selection/projection hashes unchanged across lifecycle updates. Lineage row version and confirmed native IDs are separate mutable state.
4. `findCommand` keys by tenant, actor and request UUID. Persist the complete `WebinarPublisherOperationSchema`, including `expectedRowVersion`, `requestHash`, confirmation/summary/projection hashes, native IDs at confirmation and actor-role-version provenance. The original normalized command is reconstructible from operation fields. Exact replay must preserve that identity even after the lineage row version changes.
5. `reserveCommand` atomically inserts that operation, records safe attempt provenance, CAS-updates the exact expected lineage row/state, and writes the provided `WebinarPublisherTaskSchema` to the durable outbox. One active mutating launch lineage is allowed per projection. Enforce duplicate identity/content conflicts and concurrent independent commands under real locks/constraints. Any callback exception, including a changed persistence return, rolls back the entire transaction and outbox.
6. A cancellation or pause control must safely interrupt/fence the active lineage rather than waiting for an active command to finish indefinitely. Cancellation before any dispatch prevents the old queued task from sending. If a write is already in flight, record cancellation pending/reconciliation; do not declare the remote effect recalled. A confirmed native campaign can require pause after reconciliation. No remote deletion is available.

The task JSON is exactly: `schemaVersion: 1`, `contractId: CTR-003`, `contractRevision: 1`, `kind: webinar-publisher-command`, `operationRef`, `locationRef`, `projectionHash`, `action`, `correlationRef`. No token, URL lease, raster, copy or private source snapshot is duplicated into the message. Unknown task/operation revisions refuse before dispatch.

## Durable worker consumer handoff

The durable worker owns concrete execution and persisted leases, not this author. Use `WebinarPublisherCheckpointSchema` for tenant-scoped stage CAS: operation ref, worker ref, positive generation, exact expected stage, new stage/state, confirmed native IDs, actual provider observation time and safe request/read-back hashes. The concrete repository must additionally retain the bounded lease expiry, cancellation generation, unique operation-stage attempt identity and whether an external mutation may have started. A stale generation, expired lease or changed expected stage cannot checkpoint or send.

| Action/stage    | Required evidence and transition                                                                                                                                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claim           | Resolve original operation and current sole-owner authority server-side. Verify task identity and projection hash, current cancellation and fenced bounded lease. Reconstruct the original normalized command for current authorization checks; an old ledger entry is not fresh authority. |
| Draft campaign  | `reserved/queued` to `drafting/campaign`. Fresh source, installation, qualified budget/schedule and exact provider-fetchable square receipt. Native upsert, decoded confirmed campaign/account ID, then fenced checkpoint to `adset`.                                                       |
| Draft adset     | Fresh authority and evidence immediately before mutation. Confirm exact campaign/page/target/budget/end linkage. Persist the decoded adset parent ID, then checkpoint to `ad`.                                                                                                              |
| Draft ad        | Fresh authority and exact reviewed PNG delivery. Persist decoded ad ID and parent linkage, then checkpoint to `parity`.                                                                                                                                                                     |
| Linked parity   | Independently read the actual campaign, adset and one ad. Require native comparator parity including account, copy, image, destination, Housing, geography, amount and end. Successful draft finishes `draft_ready/complete`. Do not manufacture read-back from requests.                   |
| Publish         | A separately confirmed publish command begins only from `draft_ready`. Recheck current authority, qualified capability, valid media/destination and fresh complete parity. A native acknowledgement sets `publish_queued`, then bounded progress observation uses `publishing/progress`.    |
| Observed status | Qualified linked provider evidence determines `in_review`, `live`, `paused` or safe failure. Complete progress or local task completion does not establish live. Real Facebook entity IDs, actual child standing and observation time are required before live.                             |
| Pause           | Confirmed current owned campaign and current independent pause transport proof. Set `pause_pending`, send once through qualified transport, reconcile/read-back until actual `paused`. Creative expiry or source withdrawal does not disable this control.                                  |
| Resume          | Current unexpired complete evidence, qualified mapping/media, exact parity and a separately confirmed action. Begin only from `paused`, retain original budget/end, set `resume_pending`; observe actual standing separately.                                                               |
| Cancel          | Fence queued work and set `cancelled` only when no remote write has started. An in-flight or ambiguous mutation requires pending reconciliation, never assumed cancellation or deletion.                                                                                                    |
| Uncertainty     | Possible applied write with timeout, lost/invalid response or local persistence failure sets `uncertain/reconcile`. Reconcile the same confirmed IDs. If no trustworthy identity exists, block for operator reconciliation. Never search only by display name or recreate blindly.          |
| Withdrawal      | Fresh authority/evidence refusal blocks new actionable replay and mutation. The accepted bounded best-effort safety pause needs a separate system-authority consumer and truthful `pause_pending`/failure status. This increment does not implement that watcher.                           |

Before each possible provider side effect, reload cancellation and current authority and requalify the exact source/mapping required for that action. An application reservation proof or actor-role version is historical evidence, not a reusable authorization token. Store normalized product state separately from decoded provider standing, Facebook IDs, safe failure, actual observed-at and last successful sync; absent metrics stay unavailable.
